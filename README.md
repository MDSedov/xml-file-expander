# XML File Expander

Локальное Spring Boot приложение для потокового увеличения XML-файлов перед
нагрузочным тестированием. В браузере можно выбрать исходный XML, указать
целевой размер или число дополнительных копий, проверить найденные коллекции и
задать путь сохранения результата.

Приложение не отправляет XML во внешние сервисы. По умолчанию веб-интерфейс
доступен только на компьютере, где запущено приложение.

## Возможности

- автоматический поиск коллекций `/asx:abap/asx:values/*/item`;
- явное указание одного или нескольких путей записей;
- увеличение до заданного размера (`80MiB`, `1.5GiB`, `1600MB`) или на заданное
  число копий;
- пропорциональное увеличение всех найденных коллекций;
- опциональное изменение уникальных полей только в созданных копиях;
- предварительный план с оценкой размера и состава результата;
- потоковое чтение и запись: исходный XML не загружается в память целиком;
- запись во временный файл и атомарная замена готового результата;
- проверка свободного места и защита от случайной перезаписи.

## Быстрый запуск

Требования для сборки: JDK 21 и Maven 3.9+.

```bash
mvn clean package
java -jar target/xml-file-expander-1.0.0-SNAPSHOT.jar
```

После запуска откройте:

```text
http://127.0.0.1:7080
```

Готовые файлы по умолчанию предлагается сохранять в каталоге `output` рядом с
местом запуска. В интерфейсе можно ввести другой абсолютный путь. Это путь на
компьютере, где работает приложение, а не каталог на компьютере браузера.

Остановить приложение можно сочетанием `Ctrl+C` в терминале.

## Работа через интерфейс

1. Выберите исходный XML.
2. Укажите целевой размер либо количество дополнительных копий каждой записи.
3. При необходимости раскройте расширенные параметры:
   - оставьте явные пути пустыми для автоматического поиска;
   - укажите относительные пути уникальных полей, если принимающая система
     требует разные идентификаторы;
   - кнопка «Подставить рекомендуемые» добавляет поля, обнаруженные при анализе
     текущей структуры: `IDOBJ`, `DYN_ATTR/HRP9110/item/OBJID`, `IDPERS`.
4. Постройте план и проверьте найденные коллекции, число записей и оценку
   выходного размера.
5. Укажите путь результата и запустите расширение.

Исходный файл не изменяется. Если выходной файл уже существует, приложение
потребует явно включить разрешение на перезапись.

## Перенос в закрытый контур банка

На компьютере с доступом к Maven Central один раз соберите исполняемый JAR:

```bash
mvn clean package
```

Затем перенесите в закрытый контур только файл:

```text
target/xml-file-expander-1.0.0-SNAPSHOT.jar
```

На банковском компьютере нужен только JRE/JDK 21; Maven и интернет для запуска
не требуются:

```bash
java -jar xml-file-expander-1.0.0-SNAPSHOT.jar
```

Можно сразу задать каталог результатов и другой порт:

```bash
java -jar xml-file-expander-1.0.0-SNAPSHOT.jar \
  --xml-expander.default-output-directory=/data/xml-output \
  --server.port=8090
```

По умолчанию приложение слушает только `127.0.0.1`. Если доступ действительно
нужен с других компьютеров доверенной локальной сети, это следует согласовать с
ИБ и запустить явно:

```bash
java -jar xml-file-expander-1.0.0-SNAPSHOT.jar \
  --server.address=0.0.0.0 \
  --server.port=8090
```

В таком режиме любой пользователь с сетевым доступом к порту сможет отправить
файл и указать путь записи от имени системного пользователя приложения. Поэтому
для общего сетевого размещения потребуются как минимум сетевое ограничение
доступа и аутентификация; текущий вариант рассчитан прежде всего на локальный
запуск одним оператором.

Максимальный размер загружаемого XML сейчас установлен в 2 ГБ. Параметры можно
переопределить при запуске:

```bash
java -jar xml-file-expander-1.0.0-SNAPSHOT.jar \
  --spring.servlet.multipart.max-file-size=4GB \
  --spring.servlet.multipart.max-request-size=4GB
```

## Безопасная передача структуры XML

Исходный банковский XML и реальные значения полей передавать не нужно. Для
разработки достаточно отчёта о структуре и маленького синтетического образца:

```bash
scripts/analyze_xml.sh \
  --top 200 \
  --redact-file-name \
  /path/to/source.xml > xml-analysis.txt

scripts/create_safe_sample.sh \
  --items-per-collection 5 \
  /path/to/source.xml \
  safe-sample.xml
```

`create_safe_sample.sh` сохраняет имена тегов, вложенность и несколько `item`
из каждой коллекции. Текстовые значения, атрибуты и URI пространств имён
заменяются синтетическими значениями. Перед передачей оба файла всё равно нужно
проверить по правилам информационной безопасности банка: структура тегов и
длины полей тоже являются метаданными.

Если коллекции находятся по другому пути, укажите их явно:

```bash
scripts/create_safe_sample.sh \
  --items-per-collection 5 \
  --path /root/ORGANIZATIONS/item \
  --path /root/PERSONS/item \
  /path/to/source.xml \
  safe-sample.xml
```

## Консольные скрипты

Предыдущие Bash/Python-скрипты оставлены как автономный вариант для компьютеров,
где нельзя установить Java:

```bash
scripts/analyze_xml.sh /path/to/source.xml > xml-analysis.txt
scripts/expand_xml.sh --dry-run /path/to/source.xml
scripts/expand_xml.sh --target-size 1536MiB /path/to/source.xml /path/to/expanded.xml
```

Если запуск файла `.sh` запрещён политикой прав, вызовите его явно через Bash:

```bash
bash scripts/analyze_xml.sh /path/to/source.xml > xml-analysis.txt
```
