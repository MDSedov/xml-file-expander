# XML File Expander

Проект для анализа и последующего расширения XML-файлов, которые загружаются
в корпоративный сервис `sap-uploader`, а затем через сервис `profile`
попадают в PostgreSQL.

## Как безопасно передать структуру XML

Исходный банковский XML, реальные значения полей и его снимки экрана передавать
не нужно. Для разработки достаточно двух обезличенных файлов:

1. Полного отчета о структуре без имени исходного файла:

   ```bash
   scripts/analyze_xml.sh \
     --top 200 \
     --redact-file-name \
     /path/to/source.xml > xml-analysis.txt
   ```

2. Маленького синтетического XML, на котором можно фактически запустить
   расширитель:

   ```bash
   scripts/create_safe_sample.sh \
     --items-per-collection 5 \
     /path/to/source.xml \
     safe-sample.xml
   ```

`create_safe_sample.sh` оставляет имена тегов, вложенность и первые несколько
`item` из каждой коллекции `/asx:abap/asx:values/*/item`. Все текстовые значения,
атрибуты и URI пространств имен заменяются синтетическими значениями. Одинаковые
исходные значения одного поля получают одинаковую синтетическую замену, поэтому
в образце сохраняется полезная для тестирования картина повторов.

Перед передачей файлы `xml-analysis.txt` и `safe-sample.xml` нужно открыть и
проверить по правилам информационной безопасности банка. Образец раскрывает
схему тегов, длины и предполагаемые типы значений; это тоже метаданные, передача
которых должна быть разрешена. Если в банке есть XSD и его разрешено передавать,
его также можно приложить, но для запуска расширителя все равно нужен
синтетический XML.

Если коллекции находятся по другому пути, его можно указать явно несколько раз:

```bash
scripts/create_safe_sample.sh \
  --items-per-collection 5 \
  --path /root/ORGANIZATIONS/item \
  --path /root/PERSONS/item \
  /path/to/source.xml \
  safe-sample.xml
```

После получения этих двух файлов можно добавить их в `tests/fixtures/` и
зафиксировать структуру автоматическим тестом. Все рабочие скрипты используют
только Bash и стандартную библиотеку Python 3, не обращаются в интернет и могут
быть перенесены в закрытый контур обычным архивом репозитория.

## Анализ XML

Сначала нужно запустить анализатор на исходном XML-файле и передать полученный
текстовый отчет для следующего шага разработки:

```bash
scripts/analyze_xml.sh /path/to/source.xml > xml-analysis.txt
```

Если скрипт запускается из каталога `scripts`, используйте:

```bash
./analyze_xml.sh /path/to/source.xml > xml-analysis.txt
```

Или явно через `bash`:

```bash
bash scripts/analyze_xml.sh /path/to/source.xml > xml-analysis.txt
```

Анализатор не печатает текстовые значения из XML. В отчете будут только
структура файла, повторяющиеся пути, длины полей, предполагаемые типы значений
и выборочная оценка уникальности полей. Для отчета, который будет передаваться
за пределы исходного контура, добавьте `--redact-file-name`.

## Проверка скриптов

В репозитории есть небольшой полностью синтетический пример. Он проверяет
анализ, обезличивание, расширение двух коллекций и валидность результата:

```bash
tests/test_scripts.sh
```

## Расширение XML

Скрипт расширения нужен для подготовки файла к нагрузочному тестированию.
По умолчанию он автоматически находит все коллекции сущностей вида:

```text
/asx:abap/asx:values/*/item
```

Например, в текущем файле анализатор увидел как минимум:

- `/asx:abap/asx:values/ET_ORG/item`
- `/asx:abap/asx:values/ET_PERSON/item`

Все найденные коллекции масштабируются вместе: каждая запись получает одинаковое
число копий, а остаток до целевого размера распределяется между коллекциями
примерно по их исходному байтовому весу. Это сохраняет пропорции сущностей
близкими к исходному файлу и делает нагрузку похожей на продуктивную.

По умолчанию скрипт добирает размер выходного файла примерно до `1.5GiB`:

```bash
scripts/expand_xml.sh /path/to/source.xml /path/to/expanded.xml
```

Перед созданием большого файла можно посмотреть план:

```bash
scripts/expand_xml.sh --dry-run /path/to/source.xml
```

Если нужно задать размер явно:

```bash
scripts/expand_xml.sh --target-size 1536MiB /path/to/source.xml /path/to/expanded.xml
```

Если нужно вручную ограничить список размножаемых сущностей, можно передать
один или несколько путей:

```bash
scripts/expand_xml.sh \
  --path /asx:abap/asx:values/ET_ORG/item \
  --path /asx:abap/asx:values/ET_PERSON/item \
  /path/to/source.xml \
  /path/to/expanded.xml
```

Для первого прогона достаточно команды без `--unique-field`, чтобы проверить,
как `profile` принимает файл с простым копированием записей.

Если после загрузки в `profile` появятся ошибки по уникальности полей, можно
включить изменение отдельных полей только в дубликатах:

```bash
scripts/expand_xml.sh \
  --unique-field IDOBJ \
  --unique-field DYN_ATTR/HRP9110/item/OBJID \
  --unique-field IDPERS \
  /path/to/source.xml \
  /path/to/expanded.xml
```
